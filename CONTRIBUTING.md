# Contributing to KDE KeyCast

Thank you for your interest in contributing to KDE KeyCast!

Contributions of all kinds are welcome, including bug fixes, new features, documentation improvements and suggestions.

## Before contributing

- For bug reports, please use [GitHub Issues](https://github.com/hgmarcury/kde-keycast/issues).
- For feature suggestions, please open a Feature Request.
- For larger changes, consider opening an issue first to discuss the proposed implementation.

## Contributing code

1. Fork the KDE KeyCast repository.
2. Clone your fork locally.
3. Create a new branch for your changes.
4. Make your changes and keep them focused.
5. Build the project and test your changes.
6. Commit your changes with a clear commit message.
7. Push your branch to your fork.
8. Open a Pull Request against the `master` branch of KDE KeyCast.

## Building the project

Follow the build instructions in the [README](README.md).

At minimum, make sure the project builds successfully before submitting your changes.

## Code contributions

Please keep the following guidelines in mind:

- Keep changes focused and avoid unrelated modifications.
- Follow the existing code structure and conventions.
- Preserve compatibility with KDE Plasma on Wayland.
- Do not replace the bundled modified ShowMeTheKey backend with a system-installed executable.
- Preserve applicable copyright notices and third-party license information.
- Include relevant tests or testing information whenever possible.

## Pull Requests

When opening a Pull Request:

- Explain what the change does and why it is needed.
- Reference any related issues.
- Describe how the changes were tested.
- Include screenshots or recordings when they help demonstrate UI changes.

All contributions are subject to review before being merged.

## Questions and discussions

If you have questions or want to discuss an idea, feel free to use [GitHub Discussions](https://github.com/hgmarcury/kde-keycast/discussions).

Thank you for helping make KDE KeyCast better!
